Genomic selection in papaya / Seleção genômica em mamoeiro

Costa, W. G.1

2026-09-02

English

Start here

This website is a step-by-step tutorial for genomic prediction and selection in papaya using multi-allelic SSR markers. It is designed so that a reader can follow the analytical reasoning together with the R code, rather than treating the repository as a collection of disconnected scripts.

The tutorial is intended for graduate students, researchers, and practitioners working with quantitative genetics, plant breeding, genomic prediction, or related data-analysis problems. Basic familiarity with R and statistical reasoning is recommended. Previous experience with BGLR or Bayesian genomic-prediction models is not required, because the model specifications, validation design, parameters, and diagnostics are introduced as they are used.

The analytical dataset contains 150 individuals, 34 retained SSR loci expanded into 72 allele-dosage columns, and 10 production and fruit-quality traits. Family is the only categorical fixed effect used in the prediction models.

Seven methods are compared: RR-BLUP/BRR, BayesA, BayesB, BayesB2, BayesC, Bayesian Lasso, and GBLUP.

Recommended reading path

The five modules should be read in order because each module prepares the objects used by the next one. The text preceding each code block explains what will be done, methodological parameters are described together with their role and interpretation, and longer chunks contain short internal comments to make the sequence easier to follow.

  1. Data preprocessing and diagnostics — data reading, alignment, SSR quality control, and phenotype diagnostics.
  2. Matrix construction and diagnostics — allele-dosage coding, construction of X, M, and G, and definition of the family-stratified folds.
  3. Model fitting and MCMC diagnostics — specification of the seven methods, cross-validation fitting procedure, and posterior diagnostics.
  4. Result derivation and model selection — OOF predictive metrics, DIC-based support, trait-specific method selection, genomic values, and exploratory rankings.
  5. Results presentation — integrated presentation of the main tables, figures, diagnostics, and candidate summaries.

The complete model-fitting code is shown in Module 03. Because those fits are computationally intensive, the fitting chunks are not executed automatically during routine website rendering; readers who want a full refit should execute those documented steps intentionally.

Validation scope

The cross-validation uses five folds stratified by family. With 150 individuals, each fold contains 30 validation individuals and 120 training individuals, and each candidate is evaluated once out of fold.

The genotype-derived matrices are constructed from the aligned genotyped candidate panel. During validation, only the phenotype vector is masked for the validation individuals, while their original observations are retained separately for OOF assessment. Therefore, the reported predictive performance describes prediction within the represented breeding population and should not be interpreted as leave-family-out performance for entirely new families.

The OOF genomic values are cross-fitted predictions rather than final breeding values obtained from a full-data refit. Candidate rankings are exploratory proportional prioritizations constructed only for traits with positive pooled OOF correlation, selecting the top 20% of candidates within each eligible trait. A positive OOF correlation alone is not treated as demonstrated predictive utility when its corresponding significance assessment remains weak.

Reproducibility

The rendered site committed in docs/ is the versioned record for reading and inspecting the validated tutorial. A complete computational reconstruction is a different task: the canonical Excel workbooks, generated .rds objects, most generated CSV files, and native BGLR chain files are intentionally excluded from Git. Consequently, a fresh clone does not contain all inputs required to rerun Modules 01–05 from raw data or to rebuild the illustrative M05 trace.

For a full reconstruction, obtain and verify the canonical workbooks described in the data contract, restore the renv environment, execute Modules 01 and 02, deliberately run the computationally intensive fitting blocks documented in Module 03, and then regenerate the downstream outputs consumed by Modules 04 and 05. The repository README distinguishes these reproduction modes explicitly.

Português

Comece aqui

Este site é um tutorial passo a passo de predição e seleção genômica em mamoeiro utilizando marcadores SSR multialélicos. Ele foi organizado para que o leitor acompanhe o raciocínio analítico juntamente com o código R, em vez de tratar o repositório como uma coleção de scripts desconectados.

O tutorial é destinado a estudantes de pós-graduação, pesquisadores e profissionais que trabalham com genética quantitativa, melhoramento de plantas, predição genômica ou problemas relacionados de análise de dados. Recomenda-se familiaridade básica com R e raciocínio estatístico. Experiência prévia com BGLR ou modelos Bayesianos de predição genômica não é necessária, pois as especificações dos modelos, o desenho de validação, os parâmetros e os diagnósticos são apresentados à medida que são utilizados.

O conjunto analítico contém 150 indivíduos, 34 locos SSR mantidos e expandidos em 72 colunas de dosagem alélica e 10 características de produção e qualidade dos frutos. Família é o único efeito fixo categórico utilizado nos modelos de predição.

Sete métodos são comparados: RR-BLUP/BRR, BayesA, BayesB, BayesB2, BayesC, Lasso Bayesiano e GBLUP.

Ordem recomendada de leitura

Os cinco módulos devem ser lidos em sequência, pois cada módulo prepara os objetos utilizados pelo seguinte. O texto anterior a cada bloco de código explica o que será realizado, os parâmetros metodológicos são descritos juntamente com sua função e interpretação e chunks maiores contêm comentários internos curtos para facilitar o acompanhamento da sequência.

  1. Pré-processamento e diagnóstico dos dados — leitura, alinhamento, controle de qualidade dos SSR e diagnósticos fenotípicos.
  2. Construção e diagnóstico das matrizes — codificação das dosagens alélicas, construção de X, M e G e definição dos folds estratificados por família.
  3. Ajuste dos modelos e diagnósticos MCMC — especificação dos sete métodos, procedimento de ajuste em validação cruzada e diagnósticos posteriores.
  4. Derivação dos resultados e seleção dos modelos — métricas preditivas OOF, suporte baseado em DIC, seleção do método por característica, valores genômicos e rankings exploratórios.
  5. Apresentação dos resultados — apresentação integrada das principais tabelas, figuras, diagnósticos e resumos de candidatos.

O código completo de ajuste dos modelos é apresentado no Módulo 03. Como esses ajustes são computacionalmente intensivos, os chunks de ajuste não são executados automaticamente durante a renderização rotineira do site; leitores que desejem um reajuste completo devem executar intencionalmente as etapas documentadas nesse módulo.

Escopo da validação

A validação cruzada utiliza cinco folds estratificados por família. Com 150 indivíduos, cada fold contém 30 indivíduos de validação e 120 de treinamento, e cada candidato é avaliado uma única vez fora do fold.

As matrizes derivadas dos genótipos são construídas a partir do painel alinhado de candidatos genotipados. Durante a validação, apenas o vetor fenotípico é mascarado para os indivíduos de validação, enquanto suas observações originais são mantidas separadamente para avaliação OOF. Portanto, o desempenho preditivo apresentado descreve a predição dentro da população de melhoramento representada e não deve ser interpretado como desempenho leave-family-out para famílias inteiramente novas.

Os valores genômicos OOF são predições cross-fitted, e não valores genéticos finais obtidos por um reajuste com todos os dados. Os rankings são priorizações proporcionais exploratórias construídas somente para características com correlação OOF agregada positiva, selecionando os 20% superiores dos candidatos em cada característica elegível. Uma correlação OOF positiva, isoladamente, não é tratada como utilidade preditiva demonstrada quando sua avaliação de significância correspondente permanece fraca.

Reprodutibilidade

O site renderizado e commitado em docs/ é o registro versionado para leitura e inspeção do tutorial validado. Uma reconstrução computacional completa é uma tarefa diferente: as planilhas Excel canônicas, os objetos .rds gerados, a maior parte dos CSV gerados e as cadeias nativas do BGLR são intencionalmente excluídos do Git. Consequentemente, um clone novo não contém todos os insumos necessários para refazer os Módulos 01–05 a partir dos dados brutos nem para reconstruir o trace ilustrativo do M05.

Para uma reconstrução completa, obtenha e valide as planilhas canônicas descritas no contrato dos dados, restaure o ambiente renv, execute os Módulos 01 e 02, rode deliberadamente os blocos computacionalmente intensivos documentados no Módulo 03 e então regenere as saídas posteriores consumidas pelos Módulos 04 e 05. O README do repositório distingue explicitamente esses modos de reprodução.
