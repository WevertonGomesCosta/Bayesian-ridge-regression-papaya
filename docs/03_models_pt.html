1. Objetivo

Este módulo ajusta sete métodos de predição genômica para dez características do mamoeiro usando os mesmos cinco folds de validação cruzada estratificados por família criados no Módulo 02. O objetivo é mostrar, passo a passo, como o modelo estatístico é especificado, como cada método genômico é representado no BGLR, como são obtidas as predições fora da amostra (OOF) e os valores genômicos, e como são calculados os diagnósticos MCMC.

A análise completa contém

\[ 10\ \text{características} \times 5\ \text{folds} \times 7\ \text{métodos} = 350\ \text{ajustes}. \]

Os sete métodos são RR-BLUP, BayesA, BayesB, BayesB2, BayesC, Lasso Bayesiano (BL) e GBLUP. O RR-BLUP é implementado pelo componente BRR do BGLR; portanto, RR-BLUP e regressão ridge Bayesiana não são tratados como métodos separados neste projeto (Endelman 2011; Pérez and Campos 2014).

O código de ajuste está integralmente contido neste documento R Markdown. Uma construção normal do workflowr apresenta os resultados já ajustados sem repetir os 350 modelos. Um reajuste completo é realizado somente quando a chave explícita de execução descrita na Seção 8 é habilitada.

3. Modelo estatístico

Para cada característica, o modelo comum é

\[ \mathbf y = \mathbf 1\mu + \mathbf X_F\boldsymbol\beta_F + \mathbf g + \boldsymbol\varepsilon, \]

em que \(\mu\) é o intercepto, \(\mathbf X_F\boldsymbol\beta_F\) representa o efeito fixo de família, \(\mathbf g\) é o componente genômico e \(\boldsymbol\varepsilon\) é o vetor de resíduos.

3.1 Intercepto e efeito fixo de família

O BGLR ajusta automaticamente um intercepto. Por isso, a coluna do intercepto criada no Módulo 02 é removida antes de X ser fornecida como termo FIXED. As colunas restantes codificam os efeitos de família, estimados sem contração.

X_fixed <- X[
  ,
  colnames(X) != "(Intercept)",
  drop = FALSE
]

colnames(X_fixed)
[1] "FAM2"  "FAM3"  "FAM4"  "FAM5"  "FAM6"  "FAM7"  "FAM8"  "FAM9"  "FAM10"

Aqui, model = "FIXED" refere-se ao tratamento dos coeficientes de família como efeitos fixos. Esse uso de FIXED é diferente de type = "FIXED" no Lasso Bayesiano, explicado na Seção 6.6.

3.2 Componente genômico

Para os seis métodos baseados em efeitos de marcadores,

\[ \mathbf g = \mathbf M\boldsymbol\alpha, \]

de modo que o modelo se torna

\[ \mathbf y = \mathbf 1\mu + \mathbf X_F\boldsymbol\beta_F + \mathbf M\boldsymbol\alpha + \boldsymbol\varepsilon. \]

Os métodos diferem principalmente na priori atribuída aos efeitos de marcadores \(\boldsymbol\alpha\). O GBLUP, por sua vez, modela diretamente os valores genômicos como

\[ \mathbf g \sim N(\mathbf 0,\mathbf G\sigma_g^2). \]

6.1 RR-BLUP

O RR-BLUP é implementado pelo componente BRR do BGLR. Os efeitos dos marcadores possuem uma variância Gaussiana comum, produzindo contração do tipo ridge para todos os efeitos (Endelman 2011; Pérez and Campos 2014).

6.2 BayesA

O BayesA atribui variâncias específicas aos marcadores, permitindo diferentes graus de contração entre eles (Meuwissen et al. 2001; Habier et al. 2011).

6.3 BayesB

O BayesB combina uma massa de probabilidade em zero com uma distribuição contínua para efeitos não nulos. Assim, o modelo pode realizar simultaneamente contração e seleção de variáveis.

6.4 BayesB2

BayesB2 é o nome adotado no projeto para uma parametrização específica do BayesB do BGLR; não existe um modelo separado denominado BayesB2 no BGLR. A probabilidade pretendida de efeito nulo é

\[ P(\alpha_j=0)=10^{-5}. \]

No BGLR, o BayesB é parametrizado por probIn, a probabilidade de o marcador ser incluído com efeito não nulo. Portanto,

\[ probIn = 1-10^{-5}=0.99999. \]

counts = 10^6 torna a priori beta de probIn altamente concentrada em torno desse valor.

6.5 BayesC

O BayesC também permite efeito nulo, mas os efeitos não nulos compartilham uma variância comum, em vez de possuírem variâncias específicas por marcador.

6.6 Lasso Bayesiano e o lambda fixo

O Lasso Bayesiano utiliza uma priori marginal dupla exponencial para os efeitos dos marcadores (Park and Casella 2008). No BGLR, o parâmetro de contração \(\lambda\) pode ser atualizado durante a cadeia MCMC ou mantido fixo. Nesta análise ele é mantido fixo no valor obtido pela própria calibração padrão do BGLR.

Este é o segundo uso, conceitualmente distinto, da palavra FIXED no Módulo 03:

  • model = "FIXED" descreve os efeitos de família sem penalização;
  • type = "FIXED" dentro de model = "BL" significa que lambda não é atualizado durante a cadeia MCMC.

O BGLR distribui o R2 global entre os termos lineares. O preditor contém dois termos: o termo de família FIXED e o termo genômico BL. Assim, o componente BL recebe

\[ R^2_{BL}=\frac{0.5}{2}=0.25. \]

Para a matriz de marcadores centralizada, a calibração utiliza

\[ MS_x= \frac{1}{n}\sum_j\sum_i m_{ij}^2- \sum_j\bar m_j^2, \]

e

\[ \lambda_0^2= 2\frac{1-R^2}{R^2_{BL}}MS_x. \]

O valor é calculado diretamente a partir da matriz de marcadores do Módulo 02.

BL_N_LINEAR_TERMS <- 2L
BL_COMPONENT_R2 <- R2_PRIOR / BL_N_LINEAR_TERMS

BL_MSX <-
  sum(apply(M, 2, function(x) sum(x^2))) / nrow(M) -
  sum(colMeans(M)^2)

BL_LAMBDA_SQUARED <-
  2 * (1 - R2_PRIOR) / BL_COMPONENT_R2 * BL_MSX

BL_LAMBDA <- sqrt(BL_LAMBDA_SQUARED)
BL_LAMBDA_TOLERANCE <- max(
  1e-12,
  abs(BL_LAMBDA) * BL_LAMBDA_TOLERANCE_REL
)

6.7 GBLUP

O GBLUP utiliza a matriz de relacionamento genômico G, em vez dos efeitos individuais dos marcadores. No BGLR, ele é representado por um termo RKHS com K = G, que atribui aos valores genômicos a estrutura de covariância definida por G.

8.3 Validação do lambda fixo durante o ajuste

O valor fixo do BL é verificado diretamente no objeto ajustado pelo BGLR e no arquivo nativo de lambda. Essa validação é a mesma para todos os ajustes BL e fica separada da função geral de ajuste.

validate_fixed_bl <- function(
  fit,
  save_prefix,
  run_id,
  method_name,
  lambda_update_warning_count
) {
  result <- list(
    lambda = NA_real_,
    native_value = NA_real_,
    serialization_error = NA_real_,
    native_valid = NA,
    valid = NA
  )

  if (method_name != "BL") {
    return(result)
  }

  result$lambda <- as.numeric(fit$ETA$genomic$lambda)
  lambda_error <- abs(result$lambda - BL_LAMBDA)

  lambda_trace <- scan(
    paste0(save_prefix, "ETA_genomic_lambda.dat"),
    quiet = TRUE
  )

  result$native_value <- if (length(lambda_trace) > 0L) {
    lambda_trace[1]
  } else {
    NA_real_
  }

  result$serialization_error <- if (is.finite(result$native_value)) {
    abs(result$native_value - BL_LAMBDA)
  } else {
    Inf
  }

  result$native_valid <-
    length(lambda_trace) == RAW_SAVED_SAMPLES &&
    all(is.finite(lambda_trace)) &&
    all(lambda_trace > 0) &&
    length(unique(lambda_trace)) == 1L

  result$valid <-
    length(result$lambda) == 1L &&
    is.finite(result$lambda) &&
    result$lambda > 0 &&
    lambda_error <= BL_LAMBDA_TOLERANCE &&
    result$native_valid

  if (!result$valid) {
    stop("BL FIXED-lambda contract failed for ", run_id)
  }
  if (lambda_update_warning_count > 0L) {
    stop(
      "Unexpected lambda-update warning under BL type=FIXED for ",
      run_id
    )
  }

  result
}

8.4 Ajuste de uma combinação

A função de ajuste prepara o vetor fenotípico mascarado, ajusta o modelo BGLR solicitado, captura avisos e retorna as informações necessárias para os cálculos subsequentes.

fit_one_run <- function(run_index) {
  trait_name <- run_design$Trait[run_index]
  fold_number <- run_design$Fold[run_index]
  method_name <- run_design$Method[run_index]
  run_id <- run_design$Run_id[run_index]
  run_seed <- run_design$Seed[run_index]

  bglr_run_dir <- file.path(
    BGLR_DIR,
    trait_name,
    paste0("F", fold_number),
    method_name
  )
  dir.create(bglr_run_dir, recursive = TRUE, showWarnings = FALSE)

  save_prefix <- file.path(bglr_run_dir, "bglr_")
  unlink(Sys.glob(paste0(save_prefix, "*")))

  y_observed <- phenotypes[, trait_name]
  names(y_observed) <- ids

  validation_index <- which(cv_folds$Fold == fold_number)
  training_index <- which(cv_folds$Fold != fold_number)

  y_model <- y_observed
  y_model[validation_index] <- NA_real_

  set.seed(run_seed)
  run_warning_messages <- character(0)
  fit_start <- proc.time()[["elapsed"]]

  fit <- withCallingHandlers(
    BGLR::BGLR(
      y = y_model,
      ETA = ETA_models[[method_name]],
      response_type = "gaussian",
      nIter = N_ITER,
      burnIn = BURN_IN,
      thin = THIN,
      R2 = R2_PRIOR,
      saveAt = save_prefix,
      verbose = FALSE,
      rmExistingFiles = TRUE
    ),
    warning = function(w) {
      run_warning_messages <<- c(
        run_warning_messages,
        conditionMessage(w)
      )
      invokeRestart("muffleWarning")
    }
  )

  fit_end <- proc.time()[["elapsed"]]

  tau2_warning_count <- sum(grepl(
    "tau2 was not updated",
    run_warning_messages,
    fixed = TRUE
  ))
  lambda_update_warning_count <- sum(grepl(
    "lambda was not updated",
    run_warning_messages,
    fixed = TRUE
  ))

  bl <- validate_fixed_bl(
    fit = fit,
    save_prefix = save_prefix,
    run_id = run_id,
    method_name = method_name,
    lambda_update_warning_count = lambda_update_warning_count
  )

  list(
    fit = fit,
    trait = trait_name,
    fold = fold_number,
    method = method_name,
    run_id = run_id,
    seed = run_seed,
    save_prefix = save_prefix,
    training_index = training_index,
    validation_index = validation_index,
    y_observed = y_observed,
    warning_messages = run_warning_messages,
    tau2_warning_count = tau2_warning_count,
    lambda_update_warning_count = lambda_update_warning_count,
    bl = bl,
    elapsed_seconds = fit_end - fit_start
  )
}

8.5 Predições OOF e valores genômicos

Para cada modelo ajustado,

\[ \widehat y_i = \widehat\mu+ \mathbf x_{Fi}'\widehat{\boldsymbol\beta}_F+ \widehat g_i. \]

Logo, o valor genômico é recuperado por

\[ \widehat g_i= \widehat y_i- \widehat\mu- \mathbf x_{Fi}'\widehat{\boldsymbol\beta}_F. \]

extract_prediction_outputs <- function(run) {
  fit <- run$fit

  fixed_component <- as.vector(
    X_fixed %*% fit$ETA$fixed$b
  )
  genomic_component <- as.vector(
    fit$yHat - fit$mu - fixed_component
  )

  genomic_values <- data.frame(
    Run_id = run$run_id,
    IND = ids,
    Trait = run$trait,
    Fold = run$fold,
    Method = run$method,
    Genomic_value = genomic_component
  )

  predictions <- data.frame(
    Run_id = run$run_id,
    IND = ids[run$validation_index],
    Trait = run$trait,
    Fold = run$fold,
    Method = run$method,
    Observed = run$y_observed[run$validation_index],
    Predicted = fit$yHat[run$validation_index],
    Fixed_component = fixed_component[run$validation_index],
    Genomic_component = genomic_component[run$validation_index]
  )

  list(
    genomic_values = genomic_values,
    predictions = predictions
  )
}

8.6 Métricas preditivas e de ajuste

As métricas são calculadas separadamente dentro de cada ajuste característica-fold-método. A correlação OOF, RMSE, MAE, viés e inclinação de calibração quantificam a predição; DIC e o número efetivo de parâmetros resumem o ajuste e a complexidade do modelo Bayesiano.

extract_metric_output <- function(run) {
  fit <- run$fit
  observed <- run$y_observed[run$validation_index]
  predicted <- fit$yHat[run$validation_index]

  posterior_prob_in <- c(
    fit$ETA$genomic$probIn,
    NA_real_
  )[1]

  metric <- data.frame(
    Run_id = run$run_id,
    Trait = run$trait,
    Fold = run$fold,
    Method = run$method,
    Seed = run$seed,
    Training_n = length(run$training_index),
    Validation_n = length(run$validation_index),
    Correlation = cor(observed, predicted),
    RMSE = sqrt(mean((observed - predicted)^2)),
    MAE = mean(abs(observed - predicted)),
    Prediction_bias = mean(predicted - observed),
    Regression_slope = cov(observed, predicted) / var(predicted),
    DIC = fit$fit$DIC,
    Effective_parameters = fit$fit$pD,
    Log_likelihood_at_posterior_mean = fit$fit$logLikAtPostMean,
    Posterior_mean = fit$mu,
    Posterior_mean_SD = c(fit$SD.mu, NA_real_)[1],
    Residual_variance = fit$varE,
    Residual_variance_SD = c(fit$SD.varE, NA_real_)[1],
    BL_lambda = run$bl$lambda,
    BL_lambda_native_value = run$bl$native_value,
    BL_lambda_native_serialization_error = run$bl$serialization_error,
    BL_lambda_native_valid = run$bl$native_valid,
    BL_lambda_valid = run$bl$valid,
    BGLR_warning_count = length(run$warning_messages),
    Tau2_warning_count = run$tau2_warning_count,
    Lambda_update_warning_count = run$lambda_update_warning_count,
    Posterior_probIn = posterior_prob_in,
    Elapsed_seconds = run$elapsed_seconds,
    Finite_predictions = all(is.finite(predicted))
  )

  finite_columns <- c(
    "Correlation", "RMSE", "MAE", "Prediction_bias",
    "Regression_slope", "DIC", "Effective_parameters",
    "Log_likelihood_at_posterior_mean", "Posterior_mean",
    "Residual_variance", "Elapsed_seconds"
  )

  metric$Finite_metrics <- all(
    is.finite(as.numeric(metric[, finite_columns]))
  )

  metric
}

Após a remoção do burn-in das cadeias salvas, o tamanho efetivo de amostra (ESS) e a estatística de Geweke são calculados com o pacote coda.

extract_convergence_output <- function(run) {
  residual_trace_full <- scan(
    paste0(run$save_prefix, "varE.dat"),
    quiet = TRUE
  )

  genomic_trace_table <- read.table(
    paste0(
      run$save_prefix,
      genomic_trace_suffix[run$method]
    ),
    header = genomic_trace_header[run$method],
    check.names = FALSE
  )

  genomic_trace_full <- genomic_trace_table[
    ,
    genomic_trace_column[run$method]
  ]

  posterior_index <- seq.int(
    BURN_IN_SAVED_SAMPLES + 1L,
    length(residual_trace_full)
  )

  trace_matrix <- cbind(
    Residual_variance = residual_trace_full[posterior_index],
    Genomic_parameter = genomic_trace_full[posterior_index]
  )

  trace_object <- coda::mcmc(
    trace_matrix,
    start = BURN_IN + THIN,
    thin = THIN
  )

  trace_ess <- coda::effectiveSize(trace_object)
  trace_geweke <- coda::geweke.diag(trace_object)$z

  parameter_names <- c(
    "Residual_variance",
    unname(genomic_trace_parameter[run$method])
  )

  convergence <- data.frame(
    Run_id = run$run_id,
    Trait = run$trait,
    Fold = run$fold,
    Method = run$method,
    Parameter = parameter_names,
    Retained_samples = nrow(trace_matrix),
    Posterior_mean = colMeans(trace_matrix),
    Posterior_SD = apply(trace_matrix, 2, sd),
    Effective_sample_size = as.numeric(trace_ess),
    Geweke_Z = as.numeric(trace_geweke)
  )

  convergence$Review_flag <-
    !is.finite(convergence$Effective_sample_size) |
    convergence$Effective_sample_size < ESS_REVIEW_THRESHOLD |
    !is.finite(convergence$Geweke_Z) |
    abs(convergence$Geweke_Z) > GEWEKE_REVIEW_THRESHOLD

  convergence
}

Um Review_flag indica, portanto, uma cadeia que requer inspeção. Ele não é uma regra automática de rejeição do modelo e, isoladamente, não prova falta de convergência.

13. Resumo e próxima etapa

O Módulo 03 ajusta a mesma estrutura estatística em sete métodos genômicos, utilizando família como efeito fixo e os mesmos cinco folds OOF em todas as comparações. A distinção entre model = "FIXED" para família e type = "FIXED" para o lambda do Lasso Bayesiano está explícita, e o lambda fixo é derivado da calibração do BGLR, e não do desempenho preditivo.

O Módulo 04 lê models_object.rds sem reajustar os 350 modelos. Ele combina as predições OOF, compara desempenho preditivo e DIC, revisa a estabilidade MCMC e deriva os resultados genômicos específicos de cada característica.
