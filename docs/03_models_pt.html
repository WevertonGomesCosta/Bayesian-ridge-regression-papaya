1. Objetivo

Este módulo realiza o ajuste completo, com validação cruzada, de sete métodos de predição genômica para dez características do mamoeiro. Os mesmos cinco folds determinísticos e estratificados por família são utilizados para todos os métodos e características.

A análise completa contém:

\[ 10\ \text{características} \times 5\ \text{folds} \times 7\ \text{métodos} = 350\ \text{ajustes}. \]

Todos os métodos são ajustados exclusivamente com o BGLR (Pérez and Campos 2014):

  1. RR-BLUP, implementado com o componente BRR do BGLR e a matriz completa de marcadores M;
  2. BayesA com M;
  3. BayesB com M;
  4. BayesB2 com M e probabilidade de efeito zero mantida operacionalmente próxima de \(10^{-5}\);
  5. BayesC com M;
  6. Lasso Bayesiano com M, usando o parâmetro de contração lambda fixado no valor global calibrado deterministicamente pela regra padrão do BGLR;
  7. GBLUP com a matriz de relacionamento genômico G e o componente RKHS do BGLR.

RR-BLUP e regressão ridge Bayesiana não são tratados como métodos separados. O modelo Gaussiano para os efeitos dos marcadores implementado por model = "BRR" é a implementação do RR-BLUP adotada neste projeto.

2. Contrato analítico

As matrizes construídas no Módulo 02 são utilizadas sem reconstrução específica por fold:

  • X contém o intercepto e a codificação do efeito fixo de família;
  • M contém as 72 colunas centralizadas de dosagens alélicas;
  • G contém os relacionamentos genômicos aditivos;
  • cada fold identifica 30 indivíduos de validação e 120 de treinamento.

O BGLR inclui um intercepto por padrão. Portanto, a coluna do intercepto é removida de X, restando somente as colunas associadas à família para o componente FIXED.

Para cada característica e fold, somente uma cópia do vetor fenotípico é alterada. As 30 observações de validação são substituídas por NA; X, M e G permanecem globais e inalteradas.

As configurações de MCMC seguem a seção principal de métodos do artigo de referência (Silva et al. 2021):

  • 1.000.000 de iterações;
  • 200.000 iterações de burn-in;
  • thinning igual a 4;
  • 200.000 amostras posteriores mantidas.

O parâmetro padrão do BGLR para a alocação da priori é explicitado como R2 = 0.5. Para o Lasso Bayesiano, lambda é mantido fixo no valor determinístico lambda0 obtido pela própria calibração do BGLR. Como o preditor contém dois termos em ETA (família FIXED e componente genômico BL), o BGLR aloca R2/2 ao componente BL. A matriz M é global, portanto MSx e lambda0 também são globais e idênticos para todos os traits e folds.

3. Execução reprodutível e retomável

Cada combinação de característica, fold e método possui:

  • uma semente determinística;
  • um identificador único de execução;
  • um resultado RDS compacto e individual;
  • um diretório persistente contendo os arquivos nativos gravados pelo BGLR;
  • uma linha no manifesto das execuções.

O RDS compacto é o checkpoint que determina se um ajuste estatístico está ausente durante uma reconstrução comum do módulo. Checkpoints concluídos são ignorados, portanto uma reconstrução comum não reajusta modelos já concluídos.

Na transição controlada da assinatura module03-full-v3 para a especificação BL com lambda fixo, somente o BL muda estatisticamente. Os 300 checkpoints não-BL são promovidos para a nova assinatura após validação da assinatura anterior, preservando seus resultados numéricos; os 50 ajustes BL não são promovidos e devem ser recalculados integralmente.

Os arquivos nativos do BGLR são preservados em output/models/bglr/Trait/Fold/Method/. Eles contêm as cadeias reduzidas pelo thinning gravadas pelo BGLR e são utilizados diretamente nos diagnósticos posteriores e nas apresentações gráficas finais. O RDS compacto, e não os arquivos nativos das cadeias, permanece como critério de retomada dos 350 ajustes.

Significado das configurações do ajuste

As configurações acima controlam a amostragem MCMC e as prioris; elas não são critérios de seleção entre métodos.

  • N_ITER é o número total de iterações da cadeia.
  • BURN_IN define as iterações iniciais descartadas antes dos resumos posteriores.
  • THIN determina o intervalo entre amostras gravadas. Com os valores adotados, permanecem 200.000 amostras posteriores por ajuste.
  • R2 = 0.5 é utilizado pelo BGLR para calibrar os hiperparâmetros das prioris quando eles não são fornecidos diretamente. Ele representa a proporção de variância que se espera a priori que a regressão explique e não deve ser interpretado como uma estimativa de herdabilidade (Pérez and Campos 2014).
  • No BayesB2, BAYESB2_ZERO_PROBABILITY = 1e-5 representa a probabilidade desejada de efeito nulo. Como o BGLR parametriza probIn como a probabilidade de efeito diferente de zero, utiliza-se probIn = 1 - 1e-5.
  • BAYESB2_COUNTS = 1e6 torna a priori beta de probIn extremamente concentrada em torno desse valor, aproximando a convenção de probabilidade praticamente fixa usada no artigo de referência.
  • ESS_REVIEW_THRESHOLD e GEWEKE_REVIEW_THRESHOLD são apenas limites diagnósticos para indicar cadeias que precisam de inspeção adicional. Eles não são parâmetros biológicos e não excluem automaticamente um método.

# BGLR counts both ETA terms when it allocates R2 to the BL component:
# one family FIXED term and one genomic BL term.
BL_N_LINEAR_TERMS <- 2L
BL_COMPONENT_R2 <- R2_PRIOR / BL_N_LINEAR_TERMS

# Exact BGLR default calibration used by setLT.BL when lambda is omitted.
# M is global, so MSx and lambda0 are global constants across traits/folds.
BL_MSX <-
  sum(
    apply(
      M,
      2,
      function(x) sum(x^2)
    )
  ) / nrow(M) -
  sum(
    colMeans(M)^2
  )

BL_LAMBDA_SQUARED <-
  2 *
  (1 - R2_PRIOR) /
  BL_COMPONENT_R2 *
  BL_MSX

BL_LAMBDA <- sqrt(
  BL_LAMBDA_SQUARED
)

BL_LAMBDA_TOLERANCE <- max(
  1e-12,
  abs(BL_LAMBDA) *
    BL_LAMBDA_TOLERANCE_REL
)

replace_compact_signature <- function(
  x,
  old_signature,
  new_signature
) {
  if (
    is.data.frame(x) &&
      "Signature" %in% names(x)
  ) {
    # Zero-row tables are legitimate compact-result components. For example,
    # GBLUP has no marker-effect rows because it uses K rather than M.
    if (nrow(x) == 0L) {
      x$Signature <- character(0)
      return(x)
    }

    observed <- unique(
      as.character(x$Signature)
    )

    if (
      length(observed) != 1L ||
        observed != old_signature
    ) {
      stop(
        "Previous compact result has an unexpected signature."
      )
    }

    x$Signature <- new_signature
  }

  x
}

8. Ajuste completo com pontos de retomada

O loop abaixo ajusta somente as execuções cujo arquivo compacto de resultado está ausente. Uma execução concluída nunca é recalculada durante uma reconstrução comum deste módulo. A variável de ambiente opcional PAPAYA_MAX_NEW_RUNS limita quantos novos ajustes são realizados em uma construção. O valor padrão é 350, de modo que uma construção comum ajusta todas as execuções restantes. O valor 7 permite validar um bloco completo de característica e fold com todos os métodos antes de iniciar o restante da análise.

Os arquivos nativos do BGLR são preservados permanentemente para cada novo ajuste. Para os diagnósticos de cadeia única utilizados neste módulo, duas dessas cadeias salvas são lidas diretamente:

  • variância residual;
  • um segundo escalar estocástico específico do método; para o BL com lambda fixo, esse segundo escalar é o intercepto.

Para cada cadeia estocástica, o tamanho efetivo da amostra e o diagnóstico de Geweke são calculados com o coda. No BL com lambda fixo, as duas cadeias estocásticas revisadas são a variância residual e o intercepto; lambda é validado diretamente contra o contrato determinístico. Os limites abaixo são indicadores para revisão e não regras automáticas de exclusão dos modelos:

  • ESS inferior a 1.000;
  • valor absoluto da estatística de Geweke superior a 2.
