1. Objective and analytical contract

This module transforms the official outputs from Module 03 into derived analytical results. No model is refitted and no final-presentation figure is produced here.

Derived outputs include OOF predictive performance; DIC, DIC delta, Wprob, and ER; trait-specific method decisions; fold stability; computational time; heritability and accuracy in the RR-BLUP/BRR analogue; OOF genomic values; oriented rankings; proportional selection; multi-trait recurrence; and correlations among genomic values.

Method selection follows a reproducible hierarchical rule integrating OOF performance, relative DIC fit, and chain stability. When methods are practically equivalent, RR-BLUP is preferred; decisions involving criterion conflicts or convergence flags remain explicitly marked for review.

Genomic values used for ranking are strictly OOF: each individual receives the genomic component from the fold in which its phenotype was masked. The breeding direction is predefined by trait: increase MMCOM, PRODCOM, CF, DF, EP, FFC, FFP, and SS; and decrease PRODEF and DCI. No multi-trait selection is performed.

3. OOF predictive performance

Primary metrics are calculated from the 150 out-of-sample predictions for each trait-method combination, preserving exactly one OOF prediction per individual.

pooled_metrics <- predictions |>
  group_by(Trait, Method) |>
  summarise(
    N = n(),
    r = cor(Observed, Predicted),
    RMSE = sqrt(mean((Observed - Predicted)^2)),
    MAE = mean(abs(Observed - Predicted)),
    Bias = mean(Predicted - Observed),
    Slope = cov(Observed, Predicted) / var(Predicted),
    .groups = "drop"
  ) |>
  mutate(
    t_value = r * sqrt((N - 2) / (1 - r^2)),
    p_value = 2 * pt(abs(t_value), df = N - 2, lower.tail = FALSE)
  ) |>
  select(-t_value)

fold_summary <- metrics |>
  group_by(Trait, Method) |>
  summarise(
    Mean_DIC = mean(DIC),
    SD_DIC = sd(DIC),
    Mean_fold_r = mean(Correlation),
    SD_fold_r = sd(Correlation),
    Mean_fold_RMSE = mean(RMSE),
    SD_fold_RMSE = sd(RMSE),
    Mean_fold_MAE = mean(MAE),
    SD_fold_MAE = sd(MAE),
    .groups = "drop"
  )

Pearson-correlation p-values are retained only as nominal descriptive measures because cross-validation training sets overlap across folds.

4. Method comparison

Silva et al. (Silva et al. 2021) calculated approximate model probabilities from each model’s DIC difference relative to the minimum DIC. The same logic is applied jointly to the seven methods in this project.

\[ \Delta_j=DIC_j-\min(DIC),\qquad Wprob_j=\frac{\exp(-\Delta_j/2)}{\sum_k\exp(-\Delta_k/2)},\qquad ER_j=\frac{Wprob_{\max}}{Wprob_j}. \]

model_comparison <- pooled_metrics |>
  left_join(fold_summary, by = c("Trait", "Method")) |>
  group_by(Trait) |>
  mutate(
    Delta_DIC = Mean_DIC - min(Mean_DIC),
    log_weight = -0.5 * Delta_DIC,
    stable_weight = exp(log_weight - max(log_weight)),
    Wprob = stable_weight / sum(stable_weight),
    ER = max(Wprob) / Wprob
  ) |>
  ungroup() |>
  select(
    Trait, Method, Mean_DIC, SD_DIC, Delta_DIC, Wprob, ER,
    N, r, p_value, RMSE, MAE, Bias, Slope,
    Mean_fold_r, SD_fold_r, Mean_fold_RMSE, SD_fold_RMSE,
    Mean_fold_MAE, SD_fold_MAE
  ) |>
  arrange(match(Trait, traits), Delta_DIC)

5. Method selection by trait

Selection follows an explicit hierarchy rather than combining the criteria into a single score. Out-of-sample predictive ability is the primary criterion; DIC provides complementary evidence about fit and complexity; fold stability and MCMC diagnostics indicate the robustness of the decision.

Interpretation of the model-selection parameters

  • r: Pearson correlation between observed and OOF-predicted values. Higher is better and this is the primary predictive reference.
  • p_value: nominal test of \(r=0\). It is descriptive only because cross-validation training sets overlap across folds.
  • RMSE: root mean squared error in the trait’s original unit. Lower is better and large errors receive greater penalty.
  • MAE: mean absolute error in the trait’s original unit. Lower is better and it is less sensitive to extreme errors than RMSE.
  • Bias: mean of Predicted - Observed. Values close to zero are preferred.
  • Slope: slope from regressing observed on predicted values. Values close to 1 indicate better calibration.
  • Mean_DIC: mean DIC across folds. Lower values indicate a better compromise between fit and complexity; DIC is not a direct measure of prediction.
  • Delta_DIC: difference from the minimum mean DIC for the trait. Zero identifies the best mean DIC.
  • Wprob: normalized approximate weight derived from Delta_DIC. Larger values indicate stronger relative DIC support; it is not interpreted as an exact posterior probability of the model.
  • ER: ratio of the largest Wprob to the method’s Wprob. The best value is 1; larger values indicate weaker relative support.
  • Mean_fold_r and SD_fold_r: mean and variability of fold correlations.
  • Mean_fold_RMSE and SD_fold_RMSE: mean and variability of fold RMSE.
  • Minimum_ESS, Maximum_absolute_Geweke, Parameters_flagged, and Runs_with_flags: chain diagnostics. They indicate when review is required and are not biological criteria.
  • computational time is a secondary operational criterion and should decide only between scientifically equivalent methods.

Operational equivalence criterion

To avoid selecting a different method because of a negligible numerical advantage, the project uses an operational equivalence criterion based on one standard error across folds. Because cross-validation training sets overlap, this criterion is not a formal equivalence test between models.

A method is predictively competitive when:

  1. its mean r is no more than one standard error below the best mean r; and
  2. its mean RMSE is no more than one standard error above the best mean RMSE.

DIC fit is considered similar under the operational threshold Delta_DIC <= 2. This threshold is also not a formal equivalence test.

The competitive set for selection is the intersection of predictive equivalence and DIC similarity.

RR-BLUP preference and convergence review

RR-BLUP preference is applied only when RR-BLUP belongs to the competitive set and has no convergence flags.

  • If RR-BLUP is also the predictive winner, it is selected on predictive merit and RRBLUP_preference_applied = FALSE.
  • If another method is the predictive winner but RR-BLUP belongs to the competitive set without flags, RR-BLUP is preferred and RRBLUP_preference_applied = TRUE.
  • If RR-BLUP is not an automatic candidate, the best flag-free competitive method is selected by r, followed by RMSE, MAE, and DIC.
  • If no method simultaneously satisfies predictive equivalence, DIC similarity, and absence of convergence flags, the predictive winner is retained only provisionally and Selection_requires_review = TRUE.

The preference for RR-BLUP in equivalent situations is deliberate. In the current workflow it uses a common marker-effect variance and a residual variance, allowing a direct decomposition of additive variance and heritability. This does not mean that the other Bayesian models cannot provide variance information; the advantage here is the simpler and more directly interpretable parameterization used by this project.

      TRUE ~

10. Proportional selection and multi-trait recurrence

Candidate selection is restricted to traits with positive OOF correlation and p < 0.05. Within each supported trait, the 20% most favorable individuals are selected according to the oriented ranking. The proportion is parameterized and the selected count is calculated as ceiling(SELECTION_PROPORTION * N_available).

Multi-trait recurrence remains descriptive: it counts in how many supported traits each individual belongs to the selected set. No weights are applied and no selection index is constructed.

genomic_ranking <- selected_oof_genomic_values |>
  mutate(
    Selection_score = case_when(
      Selection_objective == "increase" ~ Genomic_value,
      Selection_objective == "decrease" ~ -Genomic_value,
      TRUE ~ NA_real_

  count(Trait, name = "N_available") |>

  inner_join(
    selection_sizes |> select(Trait, N_available, N_selected),
    by = "Trait"

  group_by(Trait) |>
  summarise(
    N_available = first(N_available),
    N_selected = first(N_selected),
    Score_last_selected = Selection_score[first(N_selected)],
    Score_first_not_selected = if (
      first(N_selected) < first(N_available)
    ) {
      Selection_score[first(N_selected) + 1L]
    } else {
      NA_real_
    },
    Exact_boundary_tie = if (
      first(N_selected) < first(N_available)
    ) {
      Score_last_selected == Score_first_not_selected
    } else {
      FALSE
    },
    .groups = "drop"
  ) |>
  arrange(match(Trait, traits))
