About / Sobre

Costa, W. G.1

English

Purpose and scientific scope

This project is a worked tutorial for genomic prediction and selection in papaya using multi-allelic SSR markers. Its purpose is to make the statistical reasoning, parameter choices, code, diagnostics, and interpretation visible in a single analytical sequence.

The comparison includes RR-BLUP/BRR, BayesA, BayesB, BayesB2, BayesC, Bayesian Lasso, and GBLUP. All seven methods are implemented with BGLR (Pérez and Campos 2014). The general comparative structure is informed by the SSR-based Bayesian analysis of Silva et al. (Silva et al. 2021), while the data processing, prediction design, diagnostics, and selection rules are documented for the papaya dataset used here.

The implementation is separated into five modules: preprocessing, matrix construction, model fitting, result derivation/model selection, and final presentation. Each module has a specific role and documents the methodological decisions needed to understand the code before using its outputs downstream.

Interpretation boundaries

The family-stratified five-fold cross-validation evaluates prediction within the represented breeding population. It does not estimate leave-family-out performance for completely new families. Genotype-derived matrices are built from the aligned genotyped candidate panel, whereas the phenotypes of validation individuals are masked during each fit.

Accordingly, the genomic values used for OOF assessment are cross-fitted predictions. They should not be interpreted as final breeding values from a model refitted with all phenotypes. Trait-specific candidate rankings are exploratory proportional prioritizations constructed only for traits with positive pooled OOF correlation, selecting the top 20% of candidates within each eligible trait. A positive OOF correlation alone is not treated as demonstrated predictive utility when its corresponding significance assessment remains weak.

The tutorial also does not assume that one genomic prediction method is universally superior. Method comparison and selection are performed separately by trait under the documented predictive, DIC-based, and convergence rules.

Reproducibility and provenance

The repository preserves two different reproducibility layers. The committed docs/ site is the versioned record of the validated tutorial and can be inspected directly from a fresh clone. Full computational reconstruction requires additional local material that is intentionally excluded from Git: the canonical Excel workbooks, generated analytical objects, and native BGLR chain files.

Source-data provenance, expected filenames, hashes, and alignment invariants are documented in the data contract. R dependencies are recorded with renv, and the analytical website is generated with workflowr (Blischak et al. 2019).

The source pages in analysis/ contain the explanatory text and methodological code. Computationally intensive model-fitting chunks are shown for reproducibility but are not executed automatically during routine website rendering. A full reconstruction therefore requires restoring the canonical workbooks, recreating M01/M02 outputs, deliberately executing the documented Module 03 fitting blocks, and then regenerating the downstream M04/M05 inputs. The repository README documents this distinction explicitly.

Português

Objetivo e escopo científico

Este projeto é um tutorial aplicado de predição e seleção genômica em mamoeiro utilizando marcadores SSR multialélicos. Seu objetivo é tornar visíveis, em uma única sequência analítica, o raciocínio estatístico, as escolhas de parâmetros, o código, os diagnósticos e a interpretação.

A comparação inclui RR-BLUP/BRR, BayesA, BayesB, BayesB2, BayesC, Lasso Bayesiano e GBLUP. Os sete métodos são implementados com o BGLR (Pérez and Campos 2014). A estrutura comparativa geral é orientada pela análise bayesiana com marcadores SSR de Silva et al. (Silva et al. 2021), enquanto o processamento dos dados, o desenho de predição, os diagnósticos e as regras de seleção são documentados para o conjunto de dados de mamoeiro utilizado neste tutorial.

A implementação é separada em cinco módulos: pré-processamento, construção das matrizes, ajuste dos modelos, derivação/seleção dos resultados e apresentação final. Cada módulo possui uma função específica e documenta as decisões metodológicas necessárias para compreender o código antes de utilizar suas saídas nas etapas seguintes.

Limites de interpretação

A validação cruzada em cinco folds estratificados por família avalia a predição dentro da população de melhoramento representada. Ela não estima desempenho leave-family-out para famílias completamente novas. As matrizes derivadas dos genótipos são construídas a partir do painel alinhado de candidatos genotipados, enquanto os fenótipos dos indivíduos de validação são mascarados durante cada ajuste.

Consequentemente, os valores genômicos utilizados na avaliação OOF são predições cross-fitted. Eles não devem ser interpretados como valores genéticos finais provenientes de um modelo reajustado com todos os fenótipos. Os rankings de candidatos por característica são priorizações proporcionais exploratórias construídas somente para características com correlação OOF agregada positiva, selecionando os 20% superiores dos candidatos em cada característica elegível. Uma correlação OOF positiva, isoladamente, não é tratada como utilidade preditiva demonstrada quando sua avaliação de significância correspondente permanece fraca.

O tutorial também não assume que um método de predição genômica seja universalmente superior. A comparação e a seleção dos métodos são realizadas separadamente por característica de acordo com as regras documentadas de desempenho preditivo, DIC e convergência.

Reprodutibilidade e proveniência

O repositório preserva duas camadas diferentes de reprodutibilidade. O site commitado em docs/ é o registro versionado do tutorial validado e pode ser inspecionado diretamente a partir de um clone novo. A reconstrução computacional completa exige material local adicional que é intencionalmente excluído do Git: as planilhas Excel canônicas, os objetos analíticos gerados e as cadeias nativas do BGLR.

A proveniência dos dados-fonte, os nomes esperados, hashes e invariantes de alinhamento são documentados no contrato dos dados. As dependências R são registradas com renv e o site analítico é gerado com workflowr (Blischak et al. 2019).

As páginas-fonte em analysis/ contêm o texto explicativo e o código metodológico. Os chunks computacionalmente intensivos de ajuste dos modelos são apresentados para reprodutibilidade, mas não são executados automaticamente durante a renderização rotineira do site. Uma reconstrução completa exige, portanto, restaurar as planilhas canônicas, recriar as saídas de M01/M02, executar deliberadamente os blocos de ajuste documentados no Módulo 03 e depois regenerar os insumos posteriores de M04/M05. O README do repositório documenta explicitamente essa distinção.
